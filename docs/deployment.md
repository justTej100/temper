# Deployment

## Render Blueprint

1. Fork or connect the repository in Render and create a Blueprint from `render.yaml`.
2. Confirm service names, regions, and paid plans before applying. Persistent disks, workers,
   cron jobs, pre-deploy commands, and managed services may incur charges.
3. Keep database and Key Value resources private. Their connection strings are injected with
   `fromDatabase` and `fromService`; do not copy credentials into the dashboard.
4. Confirm the frontend URL matches `CORS_ORIGINS`. If Render changes the globally unique service
   name, update that origin before deployment.
5. Deploy. The API pre-deploy command runs `alembic upgrade head`.

`NEXT_PUBLIC_API_URL` is built from the API service host during the Next.js build. Changing the API
host requires a frontend rebuild. `ADMIN_TOKEN` is generated by Render and must only be used by
trusted operators; it must never be placed in a `NEXT_PUBLIC_*` variable.

## Storage constraints

- PostgreSQL is authoritative for markets, observations, jobs, model metadata, predictions, and
  disagreement history.
- MLflow tracking metadata uses PostgreSQL; MLflow artifacts use `/var/data/artifacts` on the
  MLflow private service disk.
- Render disks are service-local. API and worker cannot mount the MLflow disk.
- API/worker `/tmp/model_artifacts` is ephemeral scratch space. Durable model recovery must use the
  MLflow artifact URI.

## Post-deploy smoke check

```bash
export WEB_URL=https://temperature-predictor-web.onrender.com
export API_URL=https://temperature-predictor-api.onrender.com

curl --fail "$WEB_URL/"
curl --fail "$API_URL/health"
curl --fail "$API_URL/ready"
curl --fail "$API_URL/api/markets/?sort=date"
```

Then:

1. Send `POST /api/sync/` with `X-Admin-Token`.
2. Poll the returned `/api/jobs/{id}` until `complete`; inspect failure text if terminal state is
   `failed`.
3. Request one supported market forecast and observe queued → fetching → training → evaluating →
   complete.
4. Verify the detail endpoint has history, exact target-date forecast, normalized buckets, selected
   model metrics, and edge snapshots.
5. Verify the corresponding MLflow run includes parameters, metrics, dataset fingerprint, and a
   downloadable artifact.
6. Open the frontend at mobile and desktop widths and verify API Docs links to the deployed API.

The first model run can exceed a free-tier request window; the API only queues work, while the
worker performs it asynchronously.

## Rollback

Roll application services back to a known image/commit. Do not downgrade the database blindly.
Review Alembic migration reversibility and take a managed database backup first. Roll model usage
back by restoring/selecting a known MLflow run and its immutable artifact metadata; see
`operations.md`.
